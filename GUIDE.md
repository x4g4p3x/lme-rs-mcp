# lme-rs-mcp User Guide

This guide covers installing, configuring, and using the **lme-rs-mcp** Model Context Protocol server.

For the statistics engine, see the [lme-rs GUIDE](https://github.com/x4g4p3x/lme-rs/blob/master/GUIDE.md). For the protocol-neutral design and migration sequence, see [AGENT_API.md](AGENT_API.md).

## What this server is

`lme-rs-mcp` is a thin MCP transport adapter around a protocol-neutral `LmeAgentApi`. It reads local CSV files, delegates fitting and inference to `lme-rs`, caches fitted models in-process, and returns typed MCP `structuredContent` with generated `outputSchema`.

The current development version targets **lme-rs 0.2.1** and exposes seven MCP tools. New clients should prefer the semantic `fit_model` fitting entry point; the original `lme_*` names remain for compatibility and existing inference workflows.

## Architecture

```text
MCP client
    |
    | stdio MCP
    v
LmeMcpServer
    |
    | typed requests / responses
    v
LmeAgentApi
    |
    | direct Rust calls
    v
lme-rs + Polars
    |
    v
FitSession: fit_id -> CachedFit -> LmeFit
```

`LmeAgentApi` owns statistical/session semantics. MCP owns transport only. This allows another scientific protocol adapter to reuse the same operations and DTOs later.

## Installation

### Prerequisites

- Rust stable
- Network access to crates.io while building

```powershell
git clone https://github.com/x4g4p3x/lme-rs-mcp.git
cd lme-rs-mcp
cargo build --release --locked
```

Binary: `target\release\lme-rs-mcp.exe` on Windows or `target/release/lme-rs-mcp` on Unix.

When published:

```powershell
cargo install lme-rs-mcp --locked
```

Validate a checkout with:

```powershell
cargo test --locked
# or
task ci
```

The integration suite vendors both the Gaussian `sleepstudy.csv` fixture and a small Poisson random-intercept GLMM fixture.

## Client configuration

### Cursor

Add the built binary under **Cursor Settings → MCP** (or in `mcp.json`):

```json
{
  "mcpServers": {
    "lme-rs": {
      "command": "C:\\path\\to\\lme-rs-mcp.exe",
      "env": {
        "LME_MCP_DATA_ROOT": "C:\\path\\to\\csv\\data"
      }
    }
  }
}
```

Restart MCP or reload the window. The current server exposes **seven tools**.

### `LME_MCP_DATA_ROOT`

This environment variable is optional but recommended for agent use. When set:

- relative `data_path` values resolve below that directory;
- absolute paths must still canonicalize inside that directory;
- path traversal outside the configured root is rejected.

When unset, relative paths resolve from the server process working directory.

## Session model

Fits are stateful inside one server process. Both `fit_model` and `lme_fit` return a UUID `fit_id` and insert the fitted model into the same `FitSession`.

Cached records contain:

- `model_kind` (`lmm` or `glmm` today; `lm`/`nlmm` reserved for later)
- formula and CSV path
- optional REML setting
- optional GLMM family/link
- optional GLMM `n_agq`
- the unified upstream `LmeFit`

A server restart clears the session. `lme_forget_fit` removes an individual cached model. There is no TTL or disk persistence yet.

## Tool reference

All tools return typed `rmcp::Json<T>` responses. Clients receive structured JSON plus the backwards-compatible text representation generated by `rmcp`.

### `fit_model`

Semantic fitting entry point. Currently implements LMM and GLMM.

| Field | Type | Default | Semantics |
|:--|:--|:--|:--|
| `model_kind` | `"lmm"` / `"glmm"` | required | Statistical model kind |
| `formula` | string | required | Wilkinson formula |
| `data_path` | string | required | CSV path on server host |
| `reml` | boolean/null | `true` for LMM | LMM only; invalid for GLMM |
| `family` | string/null | required for GLMM | `binomial`, `poisson`, `gaussian`, `gamma` |
| `link` | string/null | canonical family link | GLMM only |
| `n_agq` | integer/null | `1` for GLMM | Must be greater than zero |

Supported explicit links are:

- Binomial: `logit`, `probit`, `cloglog`
- Poisson: `log`, `identity`, `sqrt`
- Gaussian: `identity`, `log`, `inverse`
- Gamma: `inverse`, `identity`, `log`

Model-specific options are validated. For example, `reml` on a GLMM and `family` on an LMM are errors rather than ignored fields.

#### LMM example

```json
{
  "model_kind": "lmm",
  "formula": "Reaction ~ Days + (1 | Subject)",
  "data_path": "sleepstudy.csv",
  "reml": true
}
```

If `reml` is omitted for `lmm`, it defaults to `true`.

#### Poisson GLMM example

```json
{
  "model_kind": "glmm",
  "formula": "y ~ x + (1 | group)",
  "data_path": "poisson_data.csv",
  "family": "poisson",
  "n_agq": 1
}
```

The link is omitted, so the canonical Poisson `log` link is used.

A GLMM response includes metadata such as:

```json
{
  "fit_id": "...",
  "model_kind": "glmm",
  "family": "poisson",
  "link": "log",
  "n_agq": 1,
  "reml": null,
  "num_obs": 36,
  "converged": true
}
```

### `lme_fit`

Backwards-compatible Gaussian LMM entry point. It delegates to the same semantic LMM implementation as `fit_model`.

```json
{
  "formula": "Reaction ~ Days + (1 | Subject)",
  "data_path": "sleepstudy.csv",
  "reml": true
}
```

### `lme_list_fits`

No parameters. Returns all cached `fit_id` values plus model metadata: `model_kind`, formula, path, optional REML/family/link/`n_agq`, and observation count.

### `lme_fit_summary`

```json
{ "fit_id": "..." }
```

Returns the same `FitSummary` shape used by fitting operations.

### `lme_forget_fit`

```json
{ "fit_id": "..." }
```

Drops one cached model.

### `lme_anova`

Fixed-effects Type I/II/III ANOVA with Satterthwaite or Kenward–Roger denominator degrees of freedom.

**Current restriction:** LMM only. Passing a GLMM `fit_id` is rejected explicitly.

```json
{
  "fit_id": "...",
  "ddf_method": "satterthwaite",
  "anova_type": "III"
}
```

Accepted denominator-df names include `satterthwaite`/`sat` and `kenward-roger`/`kenward_roger`/`kr`.

### `lme_boot`

Parametric or residual `bootMer`-style bootstrap refits with percentile intervals.

**Current restriction:** Gaussian LMM only. Passing a GLMM `fit_id` is rejected explicitly.

```json
{
  "fit_id": "...",
  "nsim": 200,
  "method": "parametric",
  "reml": true,
  "seed": 42,
  "n_jobs": 4,
  "level": 0.95
}
```

`nsim` and `n_jobs` must be greater than zero; `level` must be strictly between 0 and 1.

## Workflows

### New semantic GLMM workflow

1. Call `fit_model` with `model_kind = "glmm"`, formula, CSV, and family.
2. Check `converged`, `family`, `link`, and `n_agq` in the returned summary.
3. Keep the returned `fit_id` for session inspection.
4. Use `lme_fit_summary` / `lme_list_fits` as needed.
5. Call `lme_forget_fit` when the model is no longer needed.

GLMM ANOVA/bootstrap are not yet exposed through the current inference tools.

### Existing LMM workflow

1. Call either `fit_model` with `model_kind = "lmm"` or the compatibility tool `lme_fit`.
2. Check convergence.
3. Run `lme_anova` and/or `lme_boot` with the returned `fit_id`.
4. Forget the fit when done.

## Agent workflow guidance

- Prefer `fit_model` for new fitting integrations.
- Use `lme_fit` only when maintaining an existing client or workflow.
- Keep the `fit_id`; cached models are in-process only.
- Prefer `LME_MCP_DATA_ROOT` so agents can use safe filename-relative paths.
- Check `converged` before interpreting downstream statistics.
- Do not send family/link options that do not belong to the selected model kind.
- For GLMMs, omit `link` when the canonical link is desired.

## Current limitations

| Topic | Status |
|:--|:--|
| Gaussian LMM fitting | Exposed via `fit_model` and `lme_fit` |
| GLMM / `glmer` | Exposed via `fit_model` |
| GLMM families | Binomial, Poisson, Gaussian, Gamma |
| Explicit GLMM links | Supported with family compatibility checks |
| LM | Not exposed yet |
| NLMM | Not exposed yet |
| Prediction | Not exposed yet |
| Model comparison | Not exposed yet |
| Confidence intervals | Not exposed yet |
| Cross-validation | Not exposed yet |
| Marginal means | Not exposed yet |
| GLMM inference via `lme_anova` / `lme_boot` | Not exposed; tools remain LMM-only |
| Parquet / Arrow input | Not exposed; CSV only |
| Session persistence | Not implemented |
| crates.io `lme-rs` dependency | `0.2.1` |

The next fitting expansion is LM/NLMM. The broader semantic API will then add model lifecycle aliases (`model_summary`, `list_models`, `forget_model`) and operations such as prediction, comparison, confidence intervals, cross-validation, and marginal means incrementally.

## Troubleshooting

### `data_path not found`

The file must exist on the same machine as the MCP server. Use an absolute path or configure `LME_MCP_DATA_ROOT` and use a path below it.

### `outside LME_MCP_DATA_ROOT`

The canonicalized CSV path escaped the configured allowlist. Move the file under the root or intentionally widen the root.

### `unknown fit_id`

The model was forgotten or the MCP server process restarted. Use `lme_list_fits` or refit.

### `family is required for glmm models`

Supply one of `binomial`, `poisson`, `gaussian`, or `gamma`.

### `link ... is not valid for family ...`

Choose a compatible family/link pair or omit `link` to use the canonical link.

### `reml does not apply to glmm models`

Remove the `reml` field from the GLMM request. REML is an LMM option in this API.

### Fit or bootstrap is slow

GLMM optimization, AGQ, and bootstrap refits can be CPU-heavy. Keep `n_agq`, `nsim`, and parallelism intentional for model size.

### stdout pollution

MCP uses stdout for protocol traffic. Added logging should go to stderr.
